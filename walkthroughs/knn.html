k-Nearest Neighbors

A 60–75 minute guide to distance, scaling, local voting, validation-based model selection, and security operations under class imbalance.

Before class

  • Install NumPy, pandas, Matplotlib, and scikit-learn, then restart and run all cells.
  • Keep the interactive KNN lesson open to vary k before coding.
  • Define label 1 as review-worthy, not malicious. The data and labels are synthetic.
  • Write “distance is a modeling choice” where students can see it.
Opening question: What makes two authentication sessions similar, and who decides the units and relative importance?

Teaching sequence

Cells 1–3 · 7 minutes

Introduce lazy learning

KNN stores examples rather than fitting coefficients. Prediction performs most of the work: compute distances, rank examples, select k, vote.

Ask: Why is training cheap but prediction expensive? What happens as the retained history grows?
Cells 4–5 · 10 minutes

Calculate one prediction by hand

Have students compute at least one Euclidean distance before running the code. Then inspect the sorted table, nearest indices, labels, and majority vote.

distance = sqrt(sum((training_point - query) ** 2))
nearest = argsort(distances)[:k]
prediction = majority_vote(labels[nearest])
Change one thing: move the query toward the lower-left cluster or switch k from 3 to 5. Predict before rerunning.
Cells 6–9 · 10 minutes

Create imbalanced sessions and protect evaluation

The features are available at scoring time. The two-stage split yields training, validation, and test partitions while stratification preserves the review rate.

Ask: Why not choose k on the test set? What security entities might require grouped or temporal splitting?
Cells 10–11 · 8 minutes

Show that units determine neighbors

request_count spans a much larger numerical range than the other features. Without scaling, it can dominate Euclidean distance for no defensible reason.

Expected: validation average precision improves from about 0.420 unscaled to 0.611 scaled.
Ask: Is scaling always neutral? What operational meaning is introduced when each feature is measured in standard deviations?
Cells 12–13 · 10 minutes

Select neighborhood size on validation data

Compare distance-weighted KNN across candidate values. Small neighborhoods are flexible and noisy; large neighborhoods smooth local structure.

Expected: validation AP rises from 0.321 at k=1 to approximately 0.737 at k=35, the selected value.
Cells 14–16 · 15 minutes

Refit, test once, and examine the threshold

Refit the selected pipeline on the combined build partition. Read the confusion matrix by rows: 147 routine sessions are correctly rejected, 1 is sent to review, 26 review-worthy sessions are missed, and 6 are found.

Expected: test AP 0.711; review precision 0.86, recall 0.19. Accuracy 0.85 hides low minority recall.
Ask: For a fixed analyst queue, where would you move the threshold? Why should that decision use validation data rather than test data?
Cells 17–19 · 10 minutes

Visualize locality and state limitations

The two-feature boundary reveals nonlinear local voting but is not the full four-dimensional model. Close by naming prediction latency, irrelevant dimensions, duplicates, drift, and uncalibrated vote fractions.

Troubleshooting

  • Missing DecisionBoundaryDisplay: update scikit-learn.
  • Different best k: restart, run in order, and confirm random state 207.
  • AP error: pass probabilities for class 1, not hard labels.
  • Scaling leakage: keep StandardScaler inside the pipeline; never fit it before splitting.
  • Boundary is slow: reduce plotting resolution or the number of build examples for visualization only.

Extensions and exit ticket

  1. Compare Manhattan and Euclidean distance while holding the split fixed.
  2. Add a random feature and explain the curse of dimensionality.
  3. On validation data, find a threshold with at least 90% review recall and report precision.
  4. Simulate chronological drift and replace the random split with a time split.
  5. Describe a near-duplicate data-poisoning strategy and two ingestion controls.
Exit ticket: Explain why “nearest” depends on scaling, features, metric, and retained reference data.
