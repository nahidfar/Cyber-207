Before class

  • Run the notebook top to bottom with NumPy, pandas, Matplotlib, and a current scikit-learn.
  • Budget 90 minutes through model comparison; reserve text Naive Bayes and parameter inspection for an extended session.
  • Every record and message is synthetic. “Suspicious” means a generated teaching label, not a real-world finding.
  • Keep the trees/ensembles lesson open for split, bootstrap, and boosting visuals.
Opening question: If one deep tree is unstable, should we constrain it, average many trees, or build trees that correct one another? Today’s models embody all three answers.

Teaching sequence

Cells 1–4 · 12 minutes

Set up and generate imbalanced defensive features

Inspect ranges and class prevalence. The risk formula makes the synthetic mechanism visible while noise prevents perfect separation.

Ask: Which features can attackers manipulate? Which could drift as infrastructure or policy changes?
Cells 5–8 · 12 minutes

Split first and establish an evidence floor

The shared evaluate_model function records accuracy, balanced accuracy, precision, recall, F1, and ROC AUC. The dummy classifier exposes how ordinary accuracy can look acceptable under imbalance.

Expected dummy: accuracy 0.731, balanced accuracy 0.516, suspicious recall 0.204, ROC AUC 0.516.
Ask: Which metric is closest to random? Why is 73% accuracy not evidence of useful detection?
Cells 9–10 · 15 minutes

Fit one controlled tree

Translate each parameter into a structural constraint. max_depth limits rule-chain length; min_samples_leaf requires evidence in each leaf; class_weight changes error cost; ccp_alpha prunes complexity.

Expected tree: accuracy 0.691, balanced accuracy 0.757, suspicious recall 0.852. It finds many positives but pays with false alarms.
Trace a path: choose one plotted leaf and read the sequence of feature tests as an auditable rule. Then ask what an attacker could change.
Cells 11–12 · 10 minutes

Expose overfitting with depth

Training balanced accuracy should keep increasing. Held-out performance eventually plateaus or declines. A widening gap is variance, not proof that a particular depth is universally wrong.

Ask: Why is repeatedly choosing depth from this test curve itself a form of test-set leakage?
Cells 13–14 · 15 minutes

Reduce variance with bagging and random forests

Bagging

Bootstrap rows, fit trees independently, aggregate predictions. Diversity comes from seeing different samples.

Random forest

Add feature subsampling at each split so strong predictors do not force every tree into the same structure.

Expected: Bagging balanced accuracy 0.829, recall 0.759, ROC AUC 0.925. Random forest accuracy 0.909, F1 0.692, ROC AUC 0.938.
Ask: Why can many individually imperfect trees outperform one tree? What happens if all trees make highly correlated errors?
Cells 15–16 · 10 minutes

Use permutation importance carefully

A feature is shuffled on held-out data; the drop in balanced accuracy estimates how much this fitted model relied on it. Error bars come from repeated permutations.

Ask: Why is importance not causality? How can correlated features hide one another?
Cells 17–18 · 15 minutes

Build sequential corrections with boosting

AdaBoost emphasizes current mistakes; histogram gradient boosting adds trees to reduce differentiable loss and can stop early. Contrast this sequential dependence with parallel bagging.

Expected: AdaBoost accuracy 0.900, recall 0.500, ROC AUC 0.933. Histogram boosting accuracy 0.886, recall 0.463, ROC AUC 0.932.
Cells 19–20 · 10 minutes

Compare scaled KNN

Keep scaling inside the pipeline. Read the confusion matrix: 288 benign correct, 8 benign flagged, 37 suspicious missed, 17 suspicious found.

Expected: accuracy 0.871, balanced accuracy 0.644, suspicious precision 0.680, recall 0.315, ROC AUC 0.930.
Cells 21–24 · 15 minutes

Add a text baseline and inspect configuration

CountVectorizer creates nonnegative unigram/bigram counts; MultinomialNB combines smoothed token evidence with class priors. The dataset is deliberately tiny, so treat the result as mechanics—not performance evidence.

get_params(deep=True) demonstrates how to verify live estimator configuration, including pipeline paths such as model__n_neighbors.

Cells 25–26 · 8 minutes

Run controlled modifications and synthesize

Change one declared parameter at a time while holding the split and seed fixed. Close by asking which model best fits different operational costs rather than declaring one universal winner.

Troubleshooting

  • estimator argument error: use a current scikit-learn. Older releases used base_estimator.
  • AdaBoost algorithm differences: the notebook checks the installed signature before adding SAMME.
  • Parallel execution is slow: change n_jobs=-1 to 1 and reduce estimators or permutation repeats for class demonstration.
  • Metrics differ: restart and run in order with seed 207.
  • Over-interpreting importance: restate that it is conditional on model, split, metric, and correlated features.

Extensions and exit ticket

  1. Increase ccp_alpha and compare leaf count with minority recall.
  2. Remove balanced class weights and predict the confusion-matrix change.
  3. Compare 250 and 500 forest trees on runtime, OOB score, and held-out metrics.
  4. Lower boosting learning rate while increasing iterations.
  5. Test KNN neighborhoods 5, 15, and 35 with uniform versus distance weighting.
  6. Switch count vectors to TF-IDF and compare unigram versus bigram behavior.
Exit ticket: Explain in one sentence how bagging creates diversity and how boosting uses errors sequentially.
