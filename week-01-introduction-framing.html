02 · Evolution of intelligent systems

From rules to models that can act

These approaches are cumulative, not replacements. Mature security programs combine deterministic controls, learned predictions, generative interfaces, and carefully bounded automation.

RULESExperts encode known indicators and policy. Example: block a known malicious hash or impossible network path.
MACHINE LEARNINGModels infer patterns from examples. Example: score a login, classify a domain, or predict incident severity.
DEEP LEARNINGNeural networks learn representations from email text, executable bytes, malware images, graphs, and event sequences.
GENERATIVE AIFoundation models summarize incidents, explain alerts, retrieve playbook knowledge, and produce queries or reports.
AGENTIC AIA model selects tools and steps toward a goal: enrich an alert, query evidence, draft a case, then request approval.

Predict

Is this malicious? Which family? What risk score, incident severity, or containment time should we expect?

Generate

Summarize evidence, explain a model result, translate an analyst question, or retrieve relevant knowledge.

Act

Call tools and coordinate workflow with scoped permissions, observable steps, and human approval for consequential actions.

03 · Learning-system vocabulary

The language of a learning system

Before choosing an algorithm, translate the security decision into examples the machine can observe and outcomes the organization actually cares about.

Data

Raw evidence: email text, DNS requests, process trees, authentication events, packet metadata, analyst cases.

Ask: what is observable at decision time?

Features

Measurements derived from data: URL length, failed-login count, parent process, token sequence, embedding vector.

Ask: what can an attacker manipulate?

Labels

Desired outcomes: malicious/benign, malware family, incident severity, analyst disposition, time to containment.

Ask: who created this truth, and when?

One problem, three learning setups

SUPERVISEDLearn from labeled phishing and benign emails to predict a class for a new email.
UNSUPERVISEDCluster email campaigns or find unusual login patterns without reliable labels.
REINFORCEMENTChoose sequential actions from feedback, such as investigation steps or adaptive evasion; powerful and risky in security.

Problem formulation drill

Scenario: reduce account-takeover losses without locking out legitimate travelers.

In pairs, write one row: unit of prediction | available data | label | action | expensive mistake.

Sample: login event | device, geo, velocity, history | confirmed takeover within 7 days | step-up auth | missed takeover versus customer lockout.

04 · Cybersecurity before ML

The old way still matters

Traditional controls encode known badness. They are fast, inspectable, and precise. Their weakness is not age; it is brittleness under variation.

Signatures

Match a known byte sequence, hash, string, domain, or behavioral fingerprint.

Strength: precise and explainable.
Failure: unseen variants.

Heuristics

Apply expert rules such as “PowerShell plus encoded arguments plus a network call.”

Strength: generalizes modestly.
Failure: maintenance and evasion.

Human analysis

Combine context, experience, and investigation to decide what happened.

Strength: flexible reasoning.
Failure: volume and fatigue.

Rule-based detection

IF file_hash IN blocklist
THEN quarantine(file)

A crisp decision based on a feature chosen in advance.

Learned detection

risk = model(file_features)
IF risk > threshold: investigate()

A score learned from examples, converted into an operational decision.

Think · Pair · Share

Prompt: Your endpoint tool finds a process whose executable no longer exists on disk. Is that malicious?

SELECT name, path, pid
FROM processes
WHERE on_disk = 0;
  1. Name one benign explanation and one malicious explanation.
  2. What additional evidence would change your confidence?
  3. Should the system block, alert, enrich, or ignore?
05 · Adversarial variation

Same behavior. Different bytes.

Metamorphic malware rewrites its representation while preserving its behavior. A detector that memorizes surface form can lose the attacker after one harmless mutation.

malicious intent
→
rewrite code
→
same semantics
→
new signature

Surface features

Hashes, exact strings, byte n-grams, instruction sequences.

Cheap to collect; often easy to alter.

Behavioral features

System calls, control flow, persistence actions, network behavior.

Harder to collect; closer to attacker intent.

Live lab: break the signature

The toy detector looks for one exact instruction sequence. Mutate the sample without changing its final result.

MOV EAX, 1
ADD EAX, 2
CALL connect_c2
SIGNATURE MATCH // detected

Important: this is a conceptual illustration, not executable malware. Ask students which feature remains invariant across all versions.

Knowledge check

Which change best improves robustness against simple metamorphism?

06 · Learning patterns from domains

The rendezvous problem

A bot and its operator need to find each other. Hard-coding one command-and-control domain makes takedown easy; generating many possible domains changes the defender’s task.

Attacker strategy

Use a shared algorithm and date as a seed to generate hundreds of candidate domains. Register only one.

Defender strategy

Classify domains using lexical patterns, DNS behavior, registration context, and host-level evidence.

Human classifier

Select every domain you suspect was algorithmically generated. Then explain your features, not just your answers.

FEATURE HINT // length, vowels, entropy, n-grams, context
Debrief: expose the shortcut

Humans often equate “unpronounceable” with malicious. That shortcut fails on CDNs, tracking domains, internationalized names, and attacker-generated wordlists. The label must come from operational evidence, not aesthetics alone.

08 · Building trustworthy datasets

Train, validate, test

A model must be evaluated on examples it did not learn from. The split protects us from confusing memorization, repeated tuning, and leakage with generalization.

PartitionPurposeWhat may influence it?
TrainingFit coefficients or model parameters.The learning algorithm sees features and labels repeatedly.
ValidationChoose features, hyperparameters, and thresholds.Human and automated tuning decisions may use its results.
TestEstimate final performance on unseen data.Nothing until the model and decisions are frozen.

Security split: time and entity matter

train: Jan–Jun → validate: Jul → test: Aug

A random row split can leak the same host, campaign, file family, or future knowledge into every partition. Prefer a time-based holdout and group related entities when deployment predicts future events.

Temporal leakage

A feature contains an analyst disposition recorded after the alert. At prediction time, that answer does not exist.

Entity leakage

Variants of one malware family or events from one host appear in both training and test partitions.

Selection leakage

The test set is checked repeatedly until a favorable model, feature set, or threshold is found.

Leakage check

You tune a detection threshold after checking test-set results five times. What happened?

09 · A first predictive model

Linear regression: predict a house price

Larger houses often cost more. Linear regression draws a straight line through past sales and uses that line to estimate the price of a new house.

What goes into the model?

house size → fitted line → predicted price

Feature: square feet. Target: sale price. Each dot in the training data represents one house that was sold.

1 · Find the size

Start with a new 1,500-square-foot house on the horizontal axis.

2 · Meet the line

Move up from 1,500 until you reach the fitted line.

3 · Read the price

The height of the line is the predicted price: $350,000.

See the prediction and the true value

Past sales
Examples used to fit the line.

Fitted line
The model's general pattern.

Predicted value
The line says $350,000.

True value
The house sold for $380,000.

Try two predictions

Use this simple line: predicted price = $50,000 + $200 × square feet

  1. What is the predicted price for 1,000 square feet?
  2. What is the predicted price for 2,000 square feet?
  3. What important information besides size could affect the real price?

How close was the prediction?

distance = actual price − predicted price

If the house sold for $380,000 and the line predicted $350,000, the point is $30,000 above the line. That vertical distance shows how far the prediction was from the actual value.

The model predicts the value on the line for that house size. It does not simply copy the price of the nearest house.

Same idea, cybersecurity target

Instead of house price, we might predict a numeric security outcome such as hours to contain an incident. The inputs could include alert backlog and incident severity. We still train on past examples and test whether predictions are close on new examples.

10 · Synthesis

Four ideas to carry forward

1

Behavior beats appearance

Robust signals are tied to what an attacker must accomplish, not merely how one sample looks.

2

A score is not an action

Thresholds, workflows, and response costs turn predictions into security outcomes.

3

Keep the test set untouched

Training fits; validation selects; testing estimates final generalization.

4

Regression predicts a value on a line

Vertical distance shows how far an actual value is from its prediction.

Exit ticket

  1. Name one cybersecurity decision that could benefit from a learned score.
  2. Identify its data, label, prediction, action, and most expensive error.
  3. Choose a split strategy and write a simple linear baseline for the target.
