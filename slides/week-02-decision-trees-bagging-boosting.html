CYBER 207 · Trees & ensembles · 4
Impurity

How mixed is a node?

Gini impurity

$G=1-\sum_c p_c^2$

Zero when every record has the same class. For a 50/50 binary node, $G=0.5$.

Entropy

$H=-\sum_c p_c\log_2p_c$

Zero for a pure node; one bit for a 50/50 binary node.

Both prefer purer children. They often—but not always—choose the same split.

CYBER 207 · Trees & ensembles · 6
Split objective

A good split reduces weighted child impurity

$\Delta I=I(parent)-\frac{n_L}{n}I(left)-\frac{n_R}{n}I(right)$

Large decrease

Children are substantially purer than the parent and each has enough support.

Greedy limitation

The best split now may block a better global tree later. Standard training does not search every possible tree.

A high-cardinality or leaky feature can appear deceptively attractive.

CYBER 207 · Trees & ensembles · 8
Interpretation

Readable does not mean stable or causal

Useful evidence

  • Exact local decision path
  • Leaf support and class mix
  • Validation behavior by subgroup
  • Counterfactual threshold sensitivity

Invalid leap

  • Early split proves causality
  • Feature importance proves intent
  • One path explains the data-generating process
  • A tiny leaf is reliable

Correlated indicators can substitute for one another; small data changes can produce a different-looking tree.

CYBER 207 · Trees & ensembles · 12
Why bagging works

Average useful errors that are not perfectly correlated

Base learner

Deep trees have low bias but high variance: small data changes can alter splits.

Diversity

Bootstrap samples expose each tree to a different version of the evidence.

Aggregation

Independent-ish errors partly cancel; stable signal survives the vote.

If every tree makes the same mistake, voting cannot remove it.

Random forest

Bagging rows + randomizing split candidates

Bagged trees

Each tree receives a bootstrap sample, but strong predictors may dominate every tree’s top splits.

Random forest

At each split, inspect only a random subset of features. Trees become less correlated.

Feature randomness can prevent one noisy indicator from controlling the entire ensemble.

CYBER 207 · Trees & ensembles · 14
OOB and importance

Useful diagnostics—with limits

Out-of-bag evidence

A bootstrap sample contains about $63.2\%$ of unique training rows on average. Omitted rows can score trees that did not train on them.

OOB is an internal training diagnostic—not the final test set.

Feature importance

Impurity importance can favor continuous or high-cardinality variables. Correlated variables share or steal credit.

Prefer held-out permutation importance and domain review.

CYBER 207 · Trees & ensembles · 18
Two boosting families

“Focus on errors” has different mathematical meanings

AdaBoost

  • Increase influence of misclassified training examples
  • Fit the next weak classifier to weighted data
  • Weight learners by performance

Can be sensitive to mislabeled points and outliers.

Gradient boosting

  • Optimize a differentiable loss
  • Fit each tree to pseudo-residuals / negative gradients
  • Add a scaled correction

Supports varied losses and regularization.

CYBER 207 · Trees & ensembles · 21
Security evaluation

A better model is not merely more accurate

Report

  • Precision and recall for the review class
  • PR-AUC under imbalance
  • Confusion matrix and queue volume
  • Time/group-aware holdout results
  • Calibration and subgroup checks

Stress

  • Drift in attack and benign behavior
  • Poisoned or duplicated training records
  • Missing and delayed telemetry
  • Cost-sensitive threshold changes
  • Unseen infrastructure and campaigns

A model prioritizes review. It does not determine intent or guilt.

Check for understanding

Which method fits trees independently and which method makes every new tree depend on the current ensemble?

Answer

Bagging / random forest fits trees independently on varied samples and features. Boosting is sequential: each stage targets the current weighted errors or loss gradient.

Takeaways

Three ideas, one progression

Tree

Greedy recursive partitions produce readable local paths but unstable high-variance models.

Bagging

Parallel diversity and aggregation stabilize trees; random forests also randomize features.

Boosting

Sequential additive corrections build a powerful model, but can chase noisy labels.

Core question: What creates diversity, how are learners combined, and which validation evidence justifies the added complexity?
